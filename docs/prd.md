# Mini CRM 产品需求文档

## 1. 产品概述

Mini CRM 为小微销售团队提供从线索进入、分配、资格判断、持续跟进到成交/丢失的轻量客户线索管理。目标是让团队知道“谁负责、客户在哪个阶段、下一步何时做、为什么没有推进”，并通过提醒和看板减少遗漏。

## 2. 用户角色

| 角色 | 主要职责 | 数据范围 | 关键权限 |
| --- | --- | --- | --- |
| 管理员 Admin | 配置团队、成员、阶段和字典，查看全局数据 | 当前组织全部数据 | 用户与角色管理、全部线索 CRUD、分配、导入、审计 |
| 销售 Sales | 管理自己的线索和客户沟通 | 自己负责的线索；团队共享线索按策略可见 | 创建/编辑/跟进自己的线索，更新阶段，完成任务 |
| 只读成员 Viewer | 查看团队进展和报表 | 被授权的组织数据 | 只读线索、跟进、仪表盘；不能写入或导出 |
| 系统任务 Worker | 执行提醒、统计等异步作业 | 仅访问作业所需数据 | 无用户登录权限；由服务账号/队列鉴权 |

权限采用 RBAC；每个请求同时检查角色权限和组织归属，资源 ID 不得绕过组织隔离。

## 3. 核心流程

### 3.1 登录与进入工作台

用户使用邮箱/手机号和密码登录，API 返回短期 access token 与可轮换 refresh token。前端拉取当前用户、角色和组织信息，按权限渲染导航；连续失败、过期或撤销 token 必须回到登录页。

### 3.2 线索进入与分配

管理员或销售手工录入线索，也可通过导入模板批量创建。必填姓名/公司（至少一个可识别主体）和来源；管理员可将线索分配给销售。系统记录创建人、负责人、来源和时间，并避免同组织内明显重复手机号/邮箱。

### 3.3 资格判断与销售阶段

线索按“新建 → 已联系 → 需求确认 → 报价/方案 → 谈判 → 赢单/输单”推进。每次阶段变更记录操作者、时间和备注；进入赢单或输单必须填写结果信息，输单必须填写原因。

### 3.4 跟进与提醒

销售在客户详情创建电话、微信、邮件、会议等跟进记录，填写摘要、结果和下一步时间。系统为下一步创建待办/提醒，通过 BullMQ 异步生成到期提醒；已完成、已取消和逾期状态可追踪。

### 3.5 看板与复盘

工作台展示线索总量、各阶段数量、近期新增、逾期跟进和转化率。管理员可按负责人、来源、日期范围筛选；销售默认只看到自己的待办和线索。报表数据必须标注统计时间范围和时区。

## 4. 功能清单

### 4.1 认证与组织

- 登录、刷新 token、退出登录、当前用户信息。
- 管理员维护成员启用/停用、角色和负责人分配。
- 组织级数据隔离、权限拒绝统一错误码、登录审计。

### 4.2 线索管理

- 线索列表：分页、关键词、阶段、负责人、来源、创建时间筛选和排序。
- 线索新建、编辑、查看详情、归档/恢复、批量分配。
- 线索来源、标签、行业、地区等轻量字典字段。
- 去重提示；重复记录不能静默覆盖。
- CSV 模板导入（MVP 可先提供异步任务状态，不承诺复杂字段映射）。

### 4.3 阶段与跟进

- 阶段看板和阶段变更历史。
- 跟进记录 CRUD：类型、发生时间、摘要、结果、下一步。
- 待办列表：未完成、已完成、逾期、取消；支持改期和完成。
- 线索时间线聚合阶段变更、跟进和任务事件。

### 4.4 仪表盘与审计

- 线索总量、阶段漏斗、来源分布、负责人排行、近期活动。
- 管理员查看关键写操作审计日志。
- 统一空态、加载态、错误态和权限不足页面。

## 5. MVP 边界

### MVP 必须包含

- 单组织模型与 Admin/Sales/Viewer 三个角色。
- 邮箱/手机号 + 密码登录、JWT 刷新/退出、RBAC 和组织隔离。
- 线索手工 CRUD、负责人、来源、标签、阶段和去重提示。
- 跟进记录、下一步任务、逾期标识和基础提醒队列。
- 列表筛选、详情时间线、阶段看板和四类基础仪表盘指标。
- PostgreSQL 迁移/种子数据、Redis/BullMQ worker、Docker Compose 启动。
- OpenAPI 文档、核心 API 单测、登录/线索/跟进关键 E2E。

### MVP 明确不包含

- 多组织计费、套餐、SaaS 商户后台和复杂数据权限矩阵。
- 手机短信、邮件营销、微信/企业微信官方通道的真实发送。
- AI 自动总结、自动评分、推荐话术或外部大模型调用。
- 复杂客户/联系人/商机三层主数据、合同、回款、发票和财务模块。
- 移动端原生 App、离线模式、实时协同编辑。
- 高级 BI（自定义指标、跨组织报表、预测模型）和任意 Excel 字段映射。

## 6. 非功能要求

- 运行时目录：Java Spring Boot API 位于 `apps/api`，Python FastAPI 服务位于 `apps/ai`；本地 Java API 使用 `8080` 端口，PostgreSQL 宿主端口统一为 `55432`。
- API p95 在 100 个并发用户、常规列表分页下小于 500ms（不含异步导入）。
- 所有密码使用强哈希；JWT secret、数据库和 Redis 凭据不入库、不入日志。
- 关键写操作可审计；健康检查可区分 API、PostgreSQL、Redis 状态。
- 支持中文界面、桌面优先且在 1280px 宽度可用；错误信息可被用户理解。
- 所有接口和枚举以 `docs/api.md` 与 OpenAPI 为单一契约来源。
