# Mini CRM 5 分钟演示脚本

## 演示准备

- 地址：`http://localhost:8080`
- 管理员账号：`admin@example.com`
- 只读账号：`viewer@example.com`
- 本地演示密码：`password123`
- 使用 `SEED_ON_START=true` 生成演示组织、成员、线索、跟进和任务。
- 演示时准备一个未归档、状态不是终态的线索，确保可以展示跟进、状态切换和 AI 面板。

## 时间安排

| 时间 | 环节 |
| --- | --- |
| 0:00-0:30 | 登录 |
| 0:30-1:00 | 工作台 |
| 1:00-1:35 | 线索列表 |
| 1:35-2:00 | 看板 |
| 2:00-2:45 | 详情与跟进 |
| 2:45-3:25 | AI 面板 |
| 3:25-3:55 | 任务 |
| 3:55-4:30 | 统计 |
| 4:30-5:00 | 设置与只读权限 |

## 1. 登录

**做什么**

1. 打开登录页。
2. 输入 `admin@example.com` 和 `password123`。
3. 点击登录。

**看什么**

- 登录成功进入工作台。
- 左侧导航出现工作台、线索、任务、统计和设置。

**说什么**

“系统采用邮箱或手机号登录，登录后根据角色加载权限。当前使用 OWNER 管理员账号，所以能看到完整导航和管理入口。”

## 2. 工作台

**做什么**

1. 停留在工作台。
2. 指出总线索、当前状态、赢单/输单、响应时长或转化率卡片。
3. 指出今日任务和最近更新线索。

**看什么**

- 工作台总览卡片。
- 今日待办。
- 最近变化的线索。

**说什么**

“工作台优先回答两个问题：团队当前有多少机会，以及今天最应该推进什么。这里的数据来自 Java API 的 dashboard 接口，按当前账号的数据范围展示。”

## 3. 线索列表

**做什么**

1. 点击“线索”。
2. 使用状态、来源或负责人筛选。
3. 点击“新建线索”，展示表单后关闭或保存一条演示线索。

**看什么**

- 分页列表、筛选条件和状态标签。
- 新建线索需要来源，姓名和公司至少填写一个。
- 管理员可以看到分配相关操作。

**说什么**

“线索不是简单通讯录。系统记录来源、负责人、销售状态、下一次动作和标签，并在组织内对手机号和邮箱做规范化去重。”

## 4. 线索看板

**做什么**

1. 从线索列表进入“看板”。
2. 展示 `new`、`contacted`、`qualified`、`proposal`、`negotiation`、`won`、`lost` 七列。
3. 选择一条开放线索，打开状态迁移。

**看什么**

- 固定状态机的阶段列。
- 每列的线索数量和加载更多。
- 状态迁移对话框。

**说什么**

“看板使用固定状态机，销售只能按正向路径推进自己的线索，管理员可以纠正或重新打开。进入赢单或输单时，系统要求填写结果信息。”

## 5. 详情与跟进

**做什么**

1. 打开一条线索详情。
2. 展示基础信息、负责人、标签和右侧时间线。
3. 新增一次电话或微信跟进，填写摘要和下一步时间。
4. 回到时间线或跟进列表。

**看什么**

- 线索详情和可见范围。
- 跟进记录。
- 状态变更、跟进和任务事件合并的时间线。
- 填写下一步时间后自动生成的任务。

**说什么**

“跟进记录和待办是联动的。填写下一步时间后，系统创建或更新关联任务；时间线把状态、沟通和任务事件放在一起，方便复盘客户为什么推进或停滞。”

## 6. AI 面板

**做什么**

1. 在同一条线索详情向下滚动到“AI 智能跟进”。
2. 依次展示意向评分、跟进摘要、下一步建议、话术生成和沉默唤醒。
3. 点击一个建议的生成或刷新按钮。

**看什么**

- 已保存建议、加载状态和失败重试状态。
- AI 只返回建议，不自动修改线索或创建任务。
- viewer 账号可以读取已保存结果，但不能触发生成。

**说什么**

“AI 不绕过业务权限。Java 先完成鉴权、负责人校验和脱敏，再调用内部 FastAPI。结果写入 PostgreSQL，开发环境接的是 mock LLM，所以这次演示不会产生外部模型费用。”

## 7. 任务

**做什么**

1. 点击“任务”。
2. 展示“今日任务”和“全部任务”两个页签。
3. 完成刚才自动生成的任务，或者打开编辑对话框展示改期。

**看什么**

- 今日待办、全部任务、负责人筛选。
- 完成和取消操作。
- 已完成/已取消任务不能再次改期。

**说什么**

“任务有 pending、completed、cancelled 三种持久化状态，逾期是根据到期时间计算的查询结果。系统通过终态保护和操作日志避免任务状态被无意覆盖。”

## 8. 统计

**做什么**

1. 点击“统计”。
2. 调整日期范围或负责人筛选。
3. 依次指出总览、渠道、销售排名、趋势、首次响应时长和流失原因。

**看什么**

- 统计过滤条件。
- ECharts 图表和表格。
- 空数据时的空态。

**说什么**

“统计只使用当前线索状态和明确的 UTC 时间范围。当前版本先做数量、转化、周期和响应代理指标，不虚构金额、ROI 或成本数据。”

## 9. 设置

**做什么**

1. 点击“设置”。
2. 展示成员列表、筛选、新增成员和启用状态。
3. 退出管理员账号，使用 `viewer@example.com` 登录。
4. 回到线索详情或设置页。

**看什么**

- 管理员可以进入设置并维护成员。
- viewer 不显示设置入口，访问受限页面会进入无权限页。
- viewer 可以查看线索、任务和统计，但不能写入、导出或触发 AI。

**说什么**

“最后看权限边界。管理员负责团队管理，viewer 只读共享进展。权限不仅控制前端菜单，Java API 还会在每个请求上重新检查角色和组织归属。”

## 收尾

“这套系统的主线是把线索、跟进、下一步任务和复盘数据连起来，再把 AI 放在权限边界之后做辅助。它适合小团队先把销售过程跑顺，再逐步扩展金额报表、可配置阶段和 AI 生命周期治理。”
